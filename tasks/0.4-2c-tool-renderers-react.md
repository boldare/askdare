# 2c. `toolRenderers`: the React API, the default skin and the demo

- **Status:** blocked (2b)
- **Release:** 0.4
- **Lane:** Core
- **Touches hot files:** Yes (`react/headless.ts`, the API snapshot and ADR-0006)
- **Changes the public API or the protocol:** Yes: API snapshot, ADR-0006 and a minor changeset
- **Depends on:** 2b

## Goal

A developer registers React components for their tools on `Root`, and the inline chat shows each tool's payload as their component under the answer, in the headless API and in `DefaultChat`.

## Decisions to read first

ADR-0017 (the whole of "The API", "Security" and "Budget"), ADR-0011, ADR-0015

## Files and area

- `packages/askdare/src/react/root.tsx` and `context.tsx`: `toolRenderers` on `Root`, kept in the chat's context.
- A new `packages/askdare/src/react/tool-results.tsx`:
  - `ToolResults` (part `tool-results`; each card in a `tool-result` with `data-ask-tool`), in call order, an error boundary per card, a development warning once per tool name without a renderer;
  - `Link`, which reuses `safeUrl` from `markdown.tsx` and the same `target` and `rel`.
- `react/headless.ts` and `react/index.ts`: export `ToolResults`, `Link`, `ToolRendererProps`, `ToolRenderers` and `ToolUi`.
- `react/skin/message.tsx`: `<ToolResults />` under the text, before the citations; styles in `askdare.css` for the parts. The eject check (`tsconfig.eject.json`) must still pass.
- `site/`: a demo tool with a card in the inline demo, a gallery state with a card (new visual baselines for inline pages only; the iframe baselines must not change) and an e2e test.
- `docs/react.md` and `docs/tools.md`: the renderer contract, `import type` for the tools, `Link` for URLs, no `dangerouslySetInnerHTML`, images only from URLs the tool builds. `llms.txt` if it lists the API.

## Don't touch

- `protocol/*` and `chat/*`: finished in 2b; a change there goes back to a task of its own.
- `embed/loader.ts` and `widget-app/`: the iframe registers no renderers until `embedPath` (3a and its tasks).

## Definition of Done

- [ ] Unit tests: a registered renderer gets `{ data, name, callId }`, an unregistered tool renders nothing and warns once in development, a throwing renderer leaves the rest of the chat, `Link` with `javascript:` and `data:` URLs renders text, primitives under both React and Preact
- [ ] Type tests: `ToolRenderers<[typeof tool]>` rejects a component with the wrong `data`, and `Root` accepts the loose form
- [ ] The XSS suite runs against a renderer that receives hostile strings
- [ ] `react.js` within its 32 KB budget (`scripts/react-size.mjs`)
- [ ] e2e in Chromium, Firefox and WebKit: a card shows live and after a reload, a click in it sends a visitor message
- [ ] Docs updated
- [ ] Changeset (minor)
- [ ] `pnpm check` passes
