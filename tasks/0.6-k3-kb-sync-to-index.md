- **Status:** blocked (k1)

## Goal

`askdare kb sync` syncs the same knowledge folder to a pgvector index as well as to an OpenAI vector store, incrementally, and says what it embedded and what it skipped.

## Decisions to read first

- [ADR-0025](../docs/adr/0025-knowledge-index.md) (Proposed), decisions 7 and 8. CLAUDE.md: the library never reads the file system at runtime; the CLI may.
- `packages/askdare/src/cli/kb-sync.ts`, `src/openai/knowledge-sync.ts` (today's scan, front matter, `askdare.kb.json`, hashes).
- `spikes/s8-retrieval/scan.ts` and `sync.ts`.

## Files and area

- `cli/kb-sync.ts` and `cli/index.ts`: an index target next to the vector store. Choose the flag or the `askdare.kb.json` field, and how the embedding model and dimensions are given (required, no default model). The CLI builds the index with `pgvectorIndex` from `@boldare/askdare-postgres` (a dynamic import, with a clear message when the package isn't installed) and `openaiEmbedder`, from `DATABASE_URL` and `OPENAI_API_KEY`.
- Scanning stays shared with the vector-store path. Extraction and chunking come from k1. Files in other formats are skipped with a warning on the index path only.
- The printed report: added, changed, removed, unchanged, embedded and reused chunks, embedding tokens.
- Tests run against k1's in-memory index. Whichever of k3 and a3 merges second adds an end-to-end test of `kb sync` against Postgres.
- Docs: `docs/cli.md`, `docs/knowledge-base.md` (syncing to an index).
