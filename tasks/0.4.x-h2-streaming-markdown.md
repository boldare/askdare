# H2. Markdown that doesn't re-parse the whole answer on every delta

- **Status:** ready
- **Release:** 0.4.x
- **Lane:** Hygiene
- **Touches hot files:** No
- **Changes the public API or the protocol:** No
- **Depends on:** none

## Goal

A long streamed answer stays smooth: rendering cost per `text.delta` no longer grows with the length of the answer.

## Decisions to read first

- ADR-0004 (sanitized output: no raw HTML, link and image allowlists). The sanitizing rules must not change.
- The `vercel-react-best-practices` skill.

## Files and area

- `packages/askdare/src/react/markdown.tsx`: `render()` runs `Lexer.lex` on the full text on every delta, and `blocks()` rebuilds every child.
- Approach to evaluate: lex once per delta but memoize finished top-level blocks (all but the last), keyed by their raw source, so React reuses them and only the last block re-renders. Measure before choosing anything heavier.
- Keep the `Fallback` error boundary and the `plain()` fallback.

## Don't touch

Hot files, and the size budget of `@boldare/askdare/react` (`scripts/react-size.mjs`) must still pass.

## Definition of Done

- [ ] A benchmark or test showing render work per delta no longer grows with answer length (for example a 20 KB answer streamed in 1,000 deltas)
- [ ] Existing Markdown and sanitizing tests pass unchanged
- [ ] Patch changeset
- [ ] `pnpm check` and the e2e suite pass
