# 4. Bot protection: optional Turnstile and a shared-store requirement

- **Status:** blocked (task 3)
- **Release:** 0.5
- **Lane:** Core
- **Touches hot files:** Yes (`bot/define-bot.ts`, `embed/loader.ts` only if unavoidable)
- **Changes the public API or the protocol:** Yes: API snapshot, ADR-0019 and a minor changeset
- **Depends on:** 3

## Goal

An operator can choose to require a human check before a session starts, and to make a production deployment refuse to run with per-instance rate limits. Both are opt-in: without them, nothing changes.

## Decisions to read first

- ADR-0004: the `HumanVerifier` port with a Turnstile adapter, checked at session creation only, deferred on 2026-10-29 because Cloudflare's script loosens the iframe's CSP.
- ADR-0019, which takes it up again.
- ADR-0005 (loader + iframe), ADR-0006 (`RateLimitStore` is a port).

## Files and area

- A `HumanVerifier` port and a Turnstile adapter, checked on `/session` only. The CSP is widened only when a verifier is configured.
- In-memory limits in production: today `create-chat-handler.ts` only warns. Keep the warning, and add opt-in `limits.requireSharedStore: true`, which makes it refuse to start without `limits.store` (ADR-0019).
- Docs: `docs/going-public.md`, `docs/configuration.md`, `docs/custom-store.md`, and replace "Coming in 0.5" in `docs/compliance.md` section 7.

## Don't touch

The loader's 5 KB budget: the challenge lives in the iframe.
