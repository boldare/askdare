# y1. Release 0.6

- **Status:** ready
- **Release:** 0.6 (base branch `release/0.6`, then `main`)
- **Lane:** Decisions
- **Touches hot files:** No (release steps only; fixes they find become their own branches)
- **Changes the public API or the protocol:** No
- **Depends on:** z1 (every other 0.6 task is merged)

## Goal

0.6 is published to npm as `latest`, with everything the 0.6 tasks left unchecked checked first. Follow [`RELEASING.md`](../RELEASING.md) from top to bottom; this file lists only what is specific to 0.6, so that none of it is forgotten.

## Decisions to read first

- `RELEASING.md` (all sections) and ADR-0006.
- `ROADMAP.md`, "Known gaps": what 0.6 knowingly leaves open. Nothing there blocks the release, but the release notes shouldn't promise any of it.
- `docs/own-your-data.md`, "What stays at OpenAI": the wording to use about data (it is kept with you, not hidden from OpenAI).

## Steps

### Before merging into `main`

1. **Merge `main` into `release/0.6`** through a pull request with a merge commit, so `release/0.6` has the 0.5.3 version bump. Without it, the 0.5.3 changeset `history-estimate.md` would be released a second time.
2. **Read every changeset in `.changeset/` together, as the 0.6 changelog.** Check that each one is accurate, describes nothing as "coming later", has the right bump (minor for features, patch for fixes) and doesn't duplicate another. Merge or reword where they overlap.
3. **Run the live checks that no 0.6 task ran.** Each needs a key or a database; spend stays under a dollar.
   - `ASKDARE_CONTRACT_OPENAI=1 pnpm smoke`: the OpenAI store contract.
   - The stateless smoke test on an item store (`postgresConversations` or `memoryConversations`) against the live API.
   - `ASKDARE_TEST_UPSTASH=1` with a real Upstash database: the turn-log contract and the wake-up latency check. It passed against a local Redis behind the Upstash REST proxy, never against Upstash itself.
4. **Check resume on Vercel**, with the maintainer's approval for a preview deployment:
   - deploy `release/0.6` with `upstashTurnLog()` configured;
   - cut an answer's stream mid-way, for example by switching the network off in the browser's dev tools, and check that it finishes exactly once;
   - record the result in ADR-0027 and `docs/deployment.md`. They say "not yet verified" today.
5. **Work through `RELEASING.md` sections 1–4.** For 0.6 in particular:
   - the README packages table lists `@boldare/askdare-postgres`;
   - `llms.txt` and `skills/askdare/SKILL.md` know the own-store, knowledge, resume, compaction and transcript features;
   - the home page mentions 0.6.

### Publishing

6. **First release of `@boldare/askdare-postgres`.** It doesn't exist on npm yet (it is at 0.0.0), so trusted publishing can't create it. Publish its first version by hand with 2FA, then add its trusted publisher, as `RELEASING.md` section 5 says. Do this before "Version packages" merges, or its publish fails.
7. **Merge `release/0.6` into `main`** through a pull request, then merge the "Version packages" pull request.
8. **Check npm:**
   - `@boldare/askdare`, `@boldare/askdare-postgres` and `@boldare/askdare-upstash` are at their new versions, with provenance, under `latest`;
   - `npm install @boldare/askdare@latest @boldare/askdare-postgres` works in a fresh app;
   - drop the stale `rc` dist-tag (`npm dist-tag rm @boldare/askdare rc`, which needs `npm login`) unless a release candidate is planned.

### After

9. **`RELEASING.md` section 7:** the GitHub release, the site's docs, deleted branches, and sharing the news. Say plainly what "own your data" means: conversations and knowledge are kept in your database; OpenAI still processes every request, and keeps attachments.
10. **Move what this release fixed out of "Known gaps"**, and give the next release's gaps task files once it is planned.

## Don't touch

- Features. A problem the checks find becomes its own fix branch into `release/0.6` (before the merge into `main`) or `main` (after), with its own pull request.

## Definition of Done

- [ ] Steps 1–5 done, with results written where they say
- [ ] 0.6 on npm as `latest`, `@boldare/askdare-postgres` included
- [ ] GitHub release published; the site shows 0.6
