# 1a. Texts per language in `defineBot`

- **Status:** ready
- **Release:** 0.4
- **Lane:** Core
- **Touches hot files:** Yes (`bot/define-bot.ts`, `i18n/texts.ts`)
- **Changes the public API or the protocol:** Yes: API snapshot, ADR-0006 and a minor changeset
- **Depends on:** none

## Goal

A bot can define `widget.texts` per language (`{ en: {...}, pl: {...} }`), so a chat with `locale: 'auto'` shows the site owner's own texts in every language it switches to. The flat form stays valid and means "the bot's locale", or English for `auto`.

## Decisions to read first

ADR-0014 (Step 2), ADR-0008, ADR-0006

## Files and area

- `packages/askdare/src/bot/define-bot.ts`: the `texts` type, its zod schema and the resolution of the widget texts.
- `packages/askdare/src/i18n/texts.ts`: reuse `textsFor`, `canonicalLocale`, `textLocale` and `TEXT_KEYS`.
- `packages/askdare/src/server/public-config.ts`: `publicConfig` picks the overrides for the requested locale.
- Docs: the language guide and the `defineBot` reference.

## Don't touch

- the `/config` endpoint (1b);
- the store and the bridge (1c);
- the loader.

## Definition of Done

- [ ] Unit tests:
  - the flat form is unchanged;
  - the per-language form is picked by locale, falling back to the bot's locale, then English;
  - unknown text keys are rejected in both forms;
  - a language key that isn't a valid BCP 47 tag is rejected.
- [ ] The "no secrets" test still passes
- [ ] Docs updated
- [ ] Changeset
- [ ] `pnpm check` passes
