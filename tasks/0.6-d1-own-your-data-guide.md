- **Status:** blocked (a2, a3, k2, k3)

- **Touches hot files:** No

## Goal

A team can move a bot from OpenAI-hosted conversations and vector stores to their own Postgres by following one guide, end to end, and knows what that changes for privacy, cost and operations.

## Decisions to read first

- [ADR-0024](../docs/adr/0024-conversation-store.md) and [ADR-0025](../docs/adr/0025-knowledge-index.md); ADR-0010 (the docs website renders `docs/*.md`).
- `docs/privacy.md`, `docs/compliance.md`, `docs/costs.md`, `docs/deployment.md`, `docs/knowledge-base.md`, and what tasks 2, a2, a3, k2 and k3 already wrote there.

## Files and area

- New `docs/own-your-data.md`: when to move and when not to; choosing a Postgres with pgvector (Neon, Supabase, Heroku Postgres, RDS, Cloud SQL); `migrate`; `postgresConversations` and `pgvectorIndex` in the route; `kb sync` to the index; sweeping old conversations (cron on Vercel, a scheduled job on Heroku); `doctor`; what stays at OpenAI (requests' 30-day abuse monitoring, files) and how that meets ZDR and EU residency; cost and latency as S7 and S8 measured them.
- Links from `docs/compliance.md`, `docs/privacy.md`, `docs/getting-started.md` and the docs site's navigation (`site/`, navigation only).
- Run the guide once on a fresh `create-next-app` against a local Postgres, as written, and fix what doesn't work.

## Don't touch

- Library code; report gaps as issues for the owning task instead.

## Definition of Done

- [ ] The guide, followed as written, gives a working bot on Postgres with cited answers and a swept conversation
- [ ] Links in place; the docs site builds
- [ ] `pnpm check` passes
