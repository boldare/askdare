# 2b. Tool UI payloads: `defineTool({ ui })`, the `tool.ui` event and history

- **Status:** ready
- **Release:** 0.4
- **Lane:** Core
- **Touches hot files:** Yes (`protocol/*`, `docs/protocol.md`, `chat/state.ts`, `chat/reducer.ts`, the API snapshot and ADR-0006)
- **Changes the public API or the protocol:** Yes: API snapshot, ADR-0006 and a minor changeset; protocol, additive within v1
- **Depends on:** none

## Goal

A tool can turn its result into a small JSON payload for the visitor with `ui: (output) => data`. The server checks it, streams it as a `tool.ui` event, rebuilds it in the history after a reload, and the browser core keeps it on the answer as `ChatMessage.ui`. Nothing renders it yet (2c).

## Decisions to read first

ADR-0017 (the whole of "The payload" and "The protocol"), ADR-0015 (how `replies` is derived; follow the same path), ADR-0003, ADR-0006

## Files and area

- `packages/askdare/src/tools/define-tool.ts`:
  - `ui` on `ToolDefinition`, typed from `Jsonified<Output>`, validated as a function like `replies`;
  - `Tool<Name extends string = string, Ui = unknown>`, with `defineTool` inferring the name as a literal (`const` type parameter) and `Ui` from `ui`;
  - a `readToolUi(tools, calls, onError)` beside `readToolReplies`, one result per successful call in call order.
- `packages/askdare/src/protocol/`: a `tool-ui.ts` with the limits (plain JSON, 8 KB serialized, depth 8, 4 per answer) and `isToolUi`, shared by server and browser; the `tool.ui` event in `events.ts`, `schemas.ts` and `validate.ts`; `ui` on `HistoryMessage`. Update `docs/protocol.md`.
- `packages/askdare/src/openai/turn.ts` and `src/server/stream-turn.ts`: emit `tool.ui` right after a successful call's `tool.status` `done`. Log the tool's name only (never the payload) when a payload is dropped.
- `packages/askdare/src/openai/history.ts`: rebuild `ui` for every answer in the loaded page from the stored calls and outputs, attaching a turn's calls to its last visible answer. A throwing `ui` loses that card, never the conversation.
- `packages/askdare/src/chat/state.ts` and `chat/reducer.ts`: `ChatMessage.ui?: readonly ToolUi[]`, from the live event and from history; the client re-checks with `isToolUi`.
- `api/askdare.api.txt`, ADR-0006's list of the public surface, a minor changeset.

## Don't touch

- `packages/askdare/src/react/`: the React API is 2c.
- `embed/loader.ts`: nothing here needs the loader.

## Definition of Done

- [ ] Unit tests: limits (size, depth, non-JSON values, more than 4 calls), a throwing `ui`, a failed call sends nothing, live and history give the same payload, the reducer keeps payloads per answer
- [ ] A recorded stream fixture with a `tool.ui` event
- [ ] Type tests in `types-test`: `ui`'s parameter is `Jsonified<Output>`, and `Tool` keeps the name literal and the `Ui` type
- [ ] `docs/protocol.md` and `docs/tools.md` updated (what reaches the visitor, purity of `ui`)
- [ ] Changeset (minor)
- [ ] `pnpm check` passes
