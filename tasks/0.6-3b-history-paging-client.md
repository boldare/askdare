# 3b. Earlier messages in the chat

- **Status:** blocked (3a)
- **Release:** 0.6 (base branch `release/0.6`)
- **Lane:** Core
- **Touches hot files:** Yes (`chat/state.ts`, `chat/reducer.ts`, `chat/store.ts`, `chat/events.ts`, `react/headless.ts`, `i18n/texts.ts`)
- **Changes the public API or the protocol:** Yes: headless API, a text key, maybe a part name (snapshot regenerated, minor changeset)
- **Depends on:** 3a

## Goal

A visitor who comes back to a long conversation can scroll up and load earlier messages, in the widget, the inline chat and the headless API.

## Decisions to read first

- ADR-0011 (headless API), ADR-0008 (parts and tokens), ADR-0014 (texts per language), and the WCAG 2.2 AA conformance statement (`docs/accessibility.md`).
- 3a's protocol section in `docs/protocol.md`.

## Files and area

- `chat/*`: the cursor in state, a `loadEarlier` action, earlier messages prepended without losing the scroll position.
- `react/headless.ts`: expose it (for example on `useChat`) with a loading and an end state.
- The widget: a "Load earlier messages" control at the top of the message list, or loading on scroll with that control as the accessible fallback; a new `data-ask-part` if needed.
- `i18n/texts.ts` and every built-in language: the new text key or keys.
- Docs: `docs/react.md`, `docs/texts.md`.

## Don't touch

- `protocol/*`, `server/*` (3a, r3a), `embed/loader.ts`.

## Definition of Done

- [ ] Unit tests for the reducer and store; an e2e test that loads an earlier page and keeps the scroll position
- [ ] Accessibility: keyboard, screen reader announcement, focus kept
- [ ] Bundle budgets hold (headless 12 KB, React entry 34 KB, ADR-0028)
- [ ] Docs, minor changeset, snapshot regenerated
- [ ] `pnpm check` passes, visual baselines refreshed if the look changed
