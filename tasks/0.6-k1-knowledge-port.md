# k1. The `KnowledgeIndex` port, chunking and the OpenAI embedder

- **Status:** ready
- **Release:** 0.6 (base branch `release/0.6`)
- **Lane:** Ports
- **Touches hot files:** No
- **Changes the public API or the protocol:** No, not yet: the exports come with k2 (minor changeset when they do)
- **Depends on:** none

## Goal

The provider-neutral pieces of own retrieval exist inside `packages/askdare`, tested on their own: the port, the chunker with its stable source IDs, an in-memory index for tests, the contract suite and `openaiEmbedder`. The pgvector index (a3), `kb sync` (k3) and the turn (k2) build on them in parallel.

## Files and area

- New `packages/askdare/src/knowledge/`: `KnowledgeIndex`, `Embedder`, `KnowledgeDocument` (with its chunks), `KnowledgeChunk`, `Passage`, `SyncReport`; the heading-aware chunker (within one section, heading trail, tables whole when they fit, about 350 tokens at most); source IDs (`k` + 12 hex characters of the chunk hash, over title, section and text); an in-memory brute-force index for tests; the contract suite (`knowledgeIndexContract`, runner-agnostic like task 1's suites, with a fake embedder).
- `src/openai/embedder.ts`: `openaiEmbedder({ model, dimensions })`, batched, abortable, returning vectors and tokens. Its `id` is `openai:<model>:<dimensions>`. No default model.
- Text extraction for Markdown, MDX, plain text and HTML (front matter as `kb sync` reads it today, HTML text in one pass as S8's final fix does). It lives here so the CLI (k3) only calls it.

## Don't touch

- `bot/define-bot.ts`, `openai/turn.ts`, `openai/tools.ts`, `openai/citations.ts`: k2 wires retrieval into the turn.
- `cli/kb-sync.ts` (k3), `packages/askdare-postgres/` (a1, a3).
- `index.ts` exports and `@boldare/askdare/testing`: k2 exports the port, and adds the suite to the subpath that task 1 creates.
