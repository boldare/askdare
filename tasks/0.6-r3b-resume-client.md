# r3b. Resume in the chat

- **Status:** blocked (3b, r3a)
- **Release:** 0.6 (base branch `release/0.6`)
- **Lane:** Core
- **Touches hot files:** Yes (`chat/store.ts`, `chat/reducer.ts`, `chat/state.ts`, maybe `chat/events.ts`)
- **Changes the public API or the protocol:** Maybe: a chat event for a resumed answer (minor changeset if so)
- **Depends on:** 3b (chat files), r3a

## Goal

When the connection drops in the middle of an answer, the chat carries on with the rest of it instead of showing an error.

## Decisions to read first

- [ADR-0027](../docs/adr/0027-stream-resume.md) (Proposed), decision 4; ADR-0013 (chat events, metadata only).

## Files and area

- `chat/chat-client.ts` and `chat/store.ts`: track the last sequence number; on a stream that ends without `message.end` or `error`, call `POST /resume` a few times with backoff, then reload history. Shown text stays; resumed events continue it with no duplicates.
- State and reducer: a "reconnecting" status the UI can show quietly, announced politely to screen readers.
- Docs: `docs/events.md` if an event is added, `docs/troubleshooting.md`.

## Don't touch

- `server/*`, `protocol/*` (r3a).

## Definition of Done

- [ ] Unit tests: drop mid-answer then resume, resume fails then history reload, duplicates ignored
- [ ] An e2e test that cuts the stream (Playwright route abort) and sees the full answer
- [ ] Budgets hold; docs; changeset
- [ ] `pnpm check` passes
