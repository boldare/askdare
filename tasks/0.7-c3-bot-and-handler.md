# c3. Bots and the handler: `handoff`, forms, `onHandoff`, `onLead`

- **Status:** blocked (c2, p1, p3)
- **Release:** 0.7 (base branch `release/0.7`)
- **Lane:** Core
- **Touches hot files:** Yes (`bot/define-bot.ts`, `server/handler.ts`; `openai/tools.ts` and `openai/turn.ts` for the reserved tools)
- **Changes the public API or the protocol:** Yes: API snapshot and a minor changeset
- **Depends on:** c2, p1, p3, and h1 and h2 merged into `release/0.7` (they change `handler.ts` on `main`). Not at the same time as c5 (both change `handler.ts`): whichever is ready first goes first, the other rebases

## Goal

A bot turns on handoff and forms in `defineBot`; the model can call `handoff` and open a form; the handler streams the events from c1, takes form submissions, validates them with p3, calls `onHandoff` (through p1's transports) and `onLead`, with limits and without content in logs.

## Decisions to read first

- ADR-0030, ADR-0031, [ADR-0012](../docs/adr/0012-server-hooks-and-telemetry.md), [ADR-0015](../docs/adr/0015-reply-options.md) (reserved names), [ADR-0004](../docs/adr/0004-threat-model.md).
- The `openai-api` skill (tool definitions for the model).

## Files and area

- `bot/define-bot.ts`: `handoff` and `forms` options, validated; reserved tool names.
- `openai/tools.ts`, `openai/turn.ts`: the `handoff` tool and the form tool, strict schemas, under the step limits.
- `server/handler.ts`: the submit endpoint, the hooks (errors to `onError`, work through `waitUntil`), limits in `limits/limits.ts`.
- `server/public-config.ts`: the public form descriptions from p3.
- `cli/doctor.ts`: check that a transport is configured when handoff is on.

## Don't touch

- `react/*`, `i18n/texts.ts` (c4), the admin code (c5).

## Definition of Done

- [ ] Recorded-stream tests: the model hands off, opens a form, a submit passes and fails validation; limits; no values in logs
- [ ] Minor changeset; snapshot regenerated
- [ ] `/security-review` and `/code-review` before merging
- [ ] `pnpm check` passes
