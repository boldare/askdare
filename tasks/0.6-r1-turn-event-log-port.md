# r1. The `TurnEventLog` port

- **Status:** ready
- **Release:** 0.6 (base branch `release/0.6`)
- **Lane:** Ports
- **Touches hot files:** No
- **Changes the public API or the protocol:** No, not yet: r3a exports it
- **Depends on:** none

## Goal

The port that resume is built on exists and is tested on its own, with an in-memory implementation and a contract suite, so the Upstash log (r2) and the server side (r3a) can start from it.

## Decisions to read first

- [ADR-0027](../docs/adr/0027-stream-resume.md) (Proposed), decisions 1, 2 and 6.
- `spikes/s7-store/FINDINGS.md`, question 6, and `probes.ts` (p5).
- `packages/askdare/src/limits/store.ts` (`RateLimitStore`, `memoryStore`) as the shape to follow.

## Files and area

- New `packages/askdare/src/resume/`: `TurnEventLog` with `append(turnId, events)`, `read(turnId, afterSeq)`, `wait(turnId, afterSeq, timeoutMs)` and a time to live; events are protocol events with a sequence number; `memoryTurnLog()` bounded in turns, events and time; a batching writer that flushes every few events or milliseconds; the contract suite (runner-agnostic, like task 1's).

## Don't touch

- `server/stream-turn.ts`, `server/handler.ts` and `protocol/*`: r3a wires it in.
- `index.ts` exports and `@boldare/askdare/testing` (r3a adds them).
