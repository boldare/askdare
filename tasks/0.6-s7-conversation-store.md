# S7. Spike: conversations stored outside OpenAI

- **Status:** ready
- **Release:** 0.6 planning (Spikes lane; ships nothing; feeds the `ConversationStore` ADR)
- **Lane:** Spikes
- **Touches hot files:** No
- **Changes the public API or the protocol:** No (an experiment only)
- **Depends on:** none

## Goal

The shape of a `ConversationStore` port, proven on a Postgres prototype, that keeps every promise of ADR-0003 while the conversation lives in the site's own database instead of OpenAI Conversations. It also answers what stream resume after a dropped connection and history beyond the latest 100 items need from that store. It runs in parallel with S6a, S6b and S8, and its port must serve all of them: OpenAI stateless turns, Claude and Open Responses all replay the history the store gives them.

## Questions the spike answers

1. **The port.** The smallest interface (create, append items, list visible messages, settle an answer, delete with files) that both the default `openaiConversations()` and a Postgres store implement. What a turn reads from it and writes to it, and in which order, so a crash mid-turn never leaves a dangling tool call (S1: a dangling call breaks the next turn).
2. **What is stored.** Which items a turn must keep to replay (messages, tool calls and outputs, reasoning items or encrypted reasoning, citations, reply options, UI payloads) and which only to show history. Size per typical 20-turn conversation.
3. **Stateless turns on OpenAI.** Run the same turns as `turn.ts` with `store: false` and the history replayed from the Postgres prototype. Compare time to first token, cached input tokens and cost with `conversation` mode. Check `include: ['reasoning.encrypted_content']` for reasoning models.
4. **Ownership and the resume token.** The token still carries an encrypted ID (now our own). What replaces `metadata: { bot, visitor }` as defense in depth.
5. **Deletion and retention.** Deleting a conversation with its files; a retention sweep the site can run; how `AdminStore` (ADR-0016) and the transcript relate.
6. **Stream resume.** What the store must keep so a visitor whose connection dropped gets the rest of the answer (events by turn and sequence number, a short TTL), and whether that belongs in the same store or in the `RateLimitStore`-like Upstash path.
7. **Long history.** Paging beyond the latest 100 items, for both the OpenAI default and Postgres.
8. **Contract tests.** A draft of the shared test suite every store implementation runs, like the one for `RateLimitStore`.
