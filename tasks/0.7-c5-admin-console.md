# c5. The admin console (stage 1) and deletes reaching the `AdminStore`

- **Status:** blocked (p2)
- **Release:** 0.7 (base branch `release/0.7`)
- **Lane:** Core
- **Touches hot files:** Yes (`server/handler.ts`)
- **Changes the public API or the protocol:** Yes: API snapshot and a minor changeset
- **Depends on:** p2, and h1 and h2 merged into `release/0.7` (they change `handler.ts` on `main`). Not at the same time as c3

## Goal

An owner opens the console route, signs in with the admin secret or an allowlisted identity, and sees each bot's resolved configuration (secrets masked), runs `doctor` and tries the bot in a playground, as ADR-0016 stage 1 describes. With an `AdminStore` configured, deleting a conversation or sweeping old ones also deletes its transcripts, ratings and leads there. That closes the "transcripts outlive a deleted conversation" gap.

## Decisions to read first

- [ADR-0016](../docs/adr/0016-admin.md), ADR-0032, [ADR-0004](../docs/adr/0004-threat-model.md), [ADR-0008](../docs/adr/0008-ui-customization-and-themes.md), [ADR-0005](../docs/adr/0005-embedding-model.md) (how the iframe app is inlined and served).

## Files and area

- `server/handler.ts`: the console routes (off by default), Bearer token on every request, `no-store` and `frame-ancestors 'none'`; `deleteConversation` and `sweep` calling the `AdminStore`.
- A new `server/admin-console.ts` and the console app, built and inlined like `widget-app/` (`scripts/inline-assets.mjs`), never read from disk at runtime.
- `server/explain.ts`: reuse it for the resolved instructions in the playground.
- `THREAT_MODEL.md`: the console section x3 drafted, finished.

## Don't touch

- `chat/*`, `react/*`, `bot/define-bot.ts` beyond an `admin` option if ADR-0032 puts it there (agree with c3's author).
