# h3. Estimate the history from the last model call

- **Status:** in progress (`fix/history-estimate`)
- **Release:** 0.6 (a hygiene fix on `main`, shipped as 0.5.3)
- **Lane:** Hygiene
- **Touches hot files:** Yes (`server/stream-turn.ts`, `server/handler.ts`: one line each, to pass a number through)
- **Changes the public API or the protocol:** No
- **Depends on:** none (follow-up of h2, boldare/askdare#161)

## Goal

The token budget reserved before each model call counts the conversation's real history, so a conversation whose bot uses tools doesn't run out of `dailyTokensPerIp` early.

## Decisions to read first

- ADR-0004 (threat model): the reservation must still be enough when the prompt cache is cold.
- ADR-0012: `onUsage` reports raw, summed counts; don't change them.

## Files and area

- `packages/askdare/src/limits/limits.ts`: `settle` stores the history size under `ask:ci:<conversation>`, which `beginTurn` adds to the next turn's estimate. Today it stores `usage.inputTokens`, the input summed over all model calls of the turn, so after a turn with three calls the next reservation holds about three times the history. In spike S9's data that ends the default per-IP budget at turn 26 instead of about 29.
- Store the input of the turn's **last** model call instead: that is what the next turn replays. The summed `TokenUsage` doesn't carry it; take it from `onStep` in `server/stream-turn.ts` and pass it through `settle`.

## Don't touch

- `onUsage` and `TokenUsage` (raw counts, ADR-0012).
- The cached-input weighting from h2 (`budgetTokens`).
