# 7. Replace the deprecated `truncation: 'auto'`

- **Status:** ready
- **Release:** 0.5
- **Lane:** Core
- **Touches hot files:** No
- **Changes the public API or the protocol:** No (behaviour for very long conversations may change: minor changeset)
- **Depends on:** none

## Goal

askdare sends no deprecated Responses parameters, and a conversation that outgrows the model's context window still gets a clear answer or a clear error.

## Decisions to read first

- ADR-0003 and its updates (compaction ruled out as a default by spikes S5 and S5b).
- The `openai-api` skill. Check in the `openaiDeveloperDocs` MCP server what replaces `truncation` today and what the API does without it. At the time of writing, `truncation` is deprecated with no shutdown date.

## Files and area

- `packages/askdare/src/openai/turn.ts` sends `truncation: 'auto'`.
- If the API without it fails a request that overflows the context window, map that failure to an existing stable code and explain it in `docs/troubleshooting.md`. `limits.maxTurns` remains the first guard.
- `docs/costs.md` describes the current behaviour and must change with it.
- If the right replacement is a decision (for example our own trimming), write a new ADR. Don't edit ADR-0003.

## Don't touch

Compaction. It belongs to 0.6.

## Definition of Done

- [ ] Recorded-stream test for an overflowing conversation
- [ ] Docs updated
- [ ] Changeset
- [ ] `pnpm check` passes, and the daily live smoke test stays green
