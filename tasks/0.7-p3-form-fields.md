# p3. Form definitions and server-side validation

- **Status:** blocked (x2)
- **Release:** 0.7 (base branch `release/0.7`)
- **Lane:** Ports
- **Touches hot files:** No (a new module, `packages/askdare/src/forms/`)
- **Changes the public API or the protocol:** Yes: API snapshot and a minor changeset (`defineForm` or what ADR-0031 names)
- **Depends on:** x2

## Goal

A form is defined once in server code, turned into the public description the widget renders (labels per locale, no server-only fields) and validated on submit, all as plain functions with tests. c3 wires them into bots and the handler.

## Decisions to read first

- ADR-0031 (x2), [ADR-0021](../docs/adr/0021-zod-stays-a-required-peer.md), [ADR-0014](../docs/adr/0014-runtime-language.md).
- `packages/askdare/src/tools/define-tool.ts` and `protocol/tool-ui.ts`: reuse their patterns.

## Files and area

- `packages/askdare/src/forms/define-form.ts`: the closed set of field types, limits on lengths and counts.
- `packages/askdare/src/forms/public.ts`: the description sent to the widget.
- `packages/askdare/src/forms/validate.ts`: zod validation, normalized values, errors per field without echoing values.

## Don't touch

- `protocol/*`, `bot/define-bot.ts`, `server/handler.ts`, `react/*` (c1, c3, c4).

## Definition of Done

- [ ] Unit tests for every field type, limits, bad input and locales
- [ ] Minor changeset; snapshot regenerated
- [ ] `pnpm check` passes
