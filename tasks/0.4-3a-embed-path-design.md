# 3a. Design note: `embedPath`

- **Status:** ready (closes after 2a)
- **Release:** 0.4
- **Lane:** Decisions
- **Touches hot files:** No
- **Changes the public API or the protocol:** No (a decision only)
- **Depends on:** 2a, to close

## Goal

A decision on how a site serves its own UI inside the iframe of the script-tag widget, so it can use its own components and `toolRenderers`. The implementation tasks come out of it.

## Decisions to read first

ADR-0005, ADR-0008, ADR-0011, ADR-0004, and the ADR from 2a

## Files and area

Update ADR-0005 and ADR-0008, or add an ADR. It decides:
- **Configuration:** where `embedPath` is set (the bot or the loader), and how the loader builds the iframe URL.
- **The page at `embedPath`:** what it renders (`Root` with `getChatConfig`), and how it learns the bot, the language and the mode.
- **The handshake:**
  - the page joins the existing `MessagePort` bridge (`widget-app/host-bridge.ts`);
  - origin checks.
- **Headers:**
  - the headers the app must set on that page (`frame-ancestors`, `Permissions-Policy`, COOP);
  - whether askdare can set them for it.
- **Budget:** the loader is at 4,963 of its 5,120 bytes.
- **`doctor`:** what it checks.
- **Risks:**
  - ADR-0005 named the risks of rendering inside the host app (layout, proxy), and the docs should steer around them;
  - the page is same-origin with the chat route in a Next app.
