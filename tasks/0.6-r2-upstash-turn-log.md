# r2. `upstashTurnLog()`

- **Status:** blocked (r1)
- **Release:** 0.6 (base branch `release/0.6`)
- **Lane:** Add-ons
- **Touches hot files:** No
- **Changes the public API or the protocol:** Yes: a new `@boldare/askdare-upstash` export (minor changeset for that package)
- **Depends on:** r1

## Goal

Sites on several instances can resume answers across instances with the Upstash Redis they already use for rate limits.

## Decisions to read first

- [ADR-0027](../docs/adr/0027-stream-resume.md) (Proposed), decision 2.
- `packages/askdare-upstash/src/index.ts` (the rate-limit store) and its tests.
- Upstash's docs on Redis streams over its REST client: whether `XREAD BLOCK` works there. If it doesn't, `wait` polls; measure the interval that keeps latency under about 250 ms without flooding requests, and record it in ADR-0027.

## Files and area

- `packages/askdare-upstash/src/`: `upstashTurnLog({ redis, ttlSeconds? })` on a Redis stream per turn (`XADD`, `XRANGE`, `EXPIRE`), in its own file, plus its export.
- README: when to use it, and that it holds answer text for minutes.

## Don't touch

- The rate-limit store in the same package, `packages/askdare/` (r1, r3a).

- [ ] The turn log contract suite passes against a fake Redis (as the rate-limit tests do) and, behind an environment flag, a real Upstash database
- [ ] README, changeset
