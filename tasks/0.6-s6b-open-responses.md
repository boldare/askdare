## Goal

A go or no-go, backed by live runs, on the cheapest second-provider path: today's `src/openai/` code pointed with a different `baseURL` at endpoints that implement the [Open Responses](https://openresponses.org/specification) spec. It runs in parallel with S6a (native Claude), S7 (own conversation store) and S8 (own retrieval).

## Questions the spike answers

The spec covers only `POST /v1/responses` (plus `/compact` and WebSocket) and `previous_response_id`. It has no Conversations, Files or vector stores, and hosted tools are optional. So every run is **stateless**: the probe replays the full input itself, as an own store would (S7 answers how that store looks).

1. **Stream mapper.** Run the same turns as `packages/askdare/src/openai/turn.ts` through the official `openai` SDK with another `baseURL`, against two endpoints that claim support (for example OpenRouter and one more: Bedrock, Together or a local server). Does `stream-mapper.ts` turn their events into exactly today's `ProtocolEvent`s? List every event, field or end reason that differs.
2. **Tool loop.** Strict function tools, parallel calls, `tool_choice: 'none'` for the forced last step, and `suggest_replies` (ADR-0015).
3. **Usage and errors.** Does `usage` carry cached and reasoning tokens? Map each endpoint's errors (unknown model, rate limit, bad request) onto today's codes.
4. **Caching and cost.** Does a stable prefix get cached across turns of a 20-turn conversation? Cost per typical turn against today's OpenAI default.
5. **What stays OpenAI-only.** Which of `moderate`, `uploadFile`, `transcribe`, `file_search` and `diagnose` have no equivalent, and what core does when a gateway lacks them (they are already optional for `moderate`).
6. **Shape of the code.** Is a second gateway a configuration of the existing `src/openai/` module (another client, no Conversations), or a module of its own? A recommendation only.

- `spikes/s6b-open-responses/`: standalone (`pnpm install --ignore-workspace`), with `openai` pinned to the version the package uses.
  - Probe scripts that mirror `turn.ts`: the same bot instructions, tools and fixtures as S6a, so the results compare.
  - Redacted fixtures of the stream events of each endpoint.
  - `FINDINGS.md` with the verdict, the measurements, the cost of the run and an **ADR input** section.
- Model IDs and endpoint URLs appear only in the spike. Pick models the user approves; ask before the first paid run.
- Keys: in `spikes/s6b-open-responses/.env` (gitignored), from accounts with a hard spend limit. Budget: about 3 USD; stop and ask before going over.
