# a3. `@boldare/askdare-admin`: the dashboard (stage 2)

- **Status:** blocked (p2)
- **Release:** 0.7 (base branch `release/0.7`)
- **Lane:** Add-ons
- **Touches hot files:** No (a new package, `packages/askdare-admin/`)
- **Changes the public API or the protocol:** Yes: a new package, first release by hand (RELEASING.md section 5)
- **Depends on:** p2 (the port and the `AdminDashboard` type). Checked end to end after c5, which serves it

## Goal

An owner adds `adminDashboard({ prices })` to the console's options and, after signing into the console, sees cost per bot, day and model, ratings over time, new conversations, the "unanswered questions" heuristic, leads and handoffs per day with the resolution rate, the most expensive conversations, the 👎 answers with their comments, and a review of a conversation from its stored transcript (ADR-0032, decisions 5 and 9).

The package is **the dashboard only**. It plugs into the stage 1 console that core serves: no route of its own, no sign-in of its own, no hooks and no storage. Core writes the records (ADR-0032, decision 3), checks access and sets the headers.

## Files and area

- `packages/askdare-admin/`:
  - `adminDashboard({ prices? })`, returning the `AdminDashboard` value p2 defines: the dashboard's script and stylesheet, built and inlined at build time with a gzipped budget of their own, and its read handlers, which take the `AdminStore` and a query core has already validated and authorised;
  - the UI: the views above, from the store's fixed queries (`days`, `conversations`, `ratings`, `transcript`) and core's review read; conversations are addressed by the sealed references core hands out, never raw IDs;
  - `prices`: the app's prices per million input, cached input and output tokens per model ID; a model without one shows tokens and "no price". No price table or model ID in the package.
- Transcripts and comments are rendered as text, never HTML.
- A peer range on `@boldare/askdare`. No `openai` or `next` dependency or types in its `.d.ts`.
- The site page that mounts the console with `memoryAdminStore()` and the dashboard, for the e2e suite (e1), together with c5's author.

## Don't touch

- `packages/askdare/` (p2 and c5 own the core side). The other add-ons.
- No hook wiring (`onUsage`, `onFeedback`, `onTranscript`, `onHandoff`, `onLead`): core writes the records.
- No storage of lead values or handoff details (ADR-0031, ADR-0032 decision 6).
