# 2a. Design note: `toolRenderers`

- **Status:** ready
- **Release:** 0.4
- **Lane:** Decisions (in parallel with 1a–1c)
- **Touches hot files:** No
- **Changes the public API or the protocol:** No (a decision only)
- **Depends on:** none

## Goal

A decision on how developers render a tool's result with their own React component (a card, a list, a carousel), building on the reply-options payload from 0.3. The implementation tasks come out of it.

## Decisions to read first

ADR-0008, ADR-0011, ADR-0015, ADR-0004, ADR-0006

## Files and area

Update ADR-0015 or add an ADR (the `adr` skill). It decides:
- **The UI payload a tool returns:**
  - how it relates to `defineTool({ replies })`;
  - size limits;
  - what reaches the browser and what never does.
- **The API:** `toolRenderers={{ [toolName]: Component }}` on `Root` and `DefaultChat`, typed from `defineTool`.
- **The protocol:** a new event or an extension of `replies`, additive within v1, and the history after a reload.
- **Fallback:** what shows when no renderer is registered.
- **Security:**
  - no raw HTML;
  - links follow the existing allowlist;
  - the renderer is the developer's own code.
- **Budget:** the size of `@boldare/askdare/react`.
- **The script-tag widget:** how it gets renderers, through `embedPath` (3a).
