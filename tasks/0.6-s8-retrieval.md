# S8. Spike: retrieval outside OpenAI vector stores

- **Status:** ready
- **Release:** 0.6 planning (Spikes lane; ships nothing; feeds the retrieval ADR)
- **Lane:** Spikes
- **Touches hot files:** No
- **Changes the public API or the protocol:** No (an experiment only)
- **Depends on:** none

## Goal

The shape of a retrieval port, proven on a pgvector prototype, that answers from a folder of documents with citations as good as `file_search` gives today. It runs in parallel with S6a, S6b and S7, and its port must serve all three model paths: OpenAI, Claude and Open Responses.

## Decisions to read first

- ADR-0002 (OpenAI only, own tool loop), ADR-0003 (conversation state), ADR-0004 (threat model: the client never chooses vector stores or `file_id`s).
- `packages/askdare/src/openai/knowledge-sync.ts` (what `kb-sync` uploads), `citations.ts`, `turn.ts`, and the citation events in `docs/protocol.md`.
- The `openai-api` skill. For embeddings, check the live docs for the current models and prices.

## Questions the spike answers

1. **The port.** The smallest interface (sync a folder, search, delete) and what a turn does with it: retrieval as a function tool the model calls, or a search before the turn, or both. What `diagnose` checks.
2. **Sync.** Chunking, embeddings and incremental re-sync of the same folder `kb-sync` uses, with a content hash so unchanged files aren't embedded again. Cost of a first sync and a re-sync.
3. **Quality.** On the same fixtures and 20 or more questions, compare answers and citations with `file_search`: right document cited, quote present, no invented sources. Write the questions and grading down so P1 can reuse them for `askdare eval` (0.8).
4. **Citations.** How results map onto our citation protocol without changing it, and how Claude's citation blocks would map (S6a sends a stub; agree the shape through `FINDINGS.md`).
5. **Untrusted content.** Retrieved text is marked as untrusted for the model, like tool results under ADR-0019.
6. **Footprint.** What a site has to run (Postgres with pgvector, an embeddings key) and whether a lighter option (a hosted vector database, an in-process index for small sites) is worth a second implementation.
