# c1. The commit-message hook in a path with a space

- **Status:** ready
- **Release:** none (tooling, lands on `main`)
- **Lane:** CI
- **Touches hot files:** No
- **Changes the public API or the protocol:** No
- **Depends on:** none

## Goal

`git commit` runs commitlint in any checkout, including worktrees under a path with a space ("open source"), so nobody needs `LEFTHOOK_EXCLUDE=commitlint`.

## Decisions to read first

- `spikes/s7-store/FINDINGS.md`, "Out of scope": `commitlint --edit {1}` in `lefthook.yml` fails when the checkout path contains a space.
- ADR-0007 (tooling).

## Files and area

- `lefthook.yml`: quote the argument (`--edit "{1}"`), or whatever lefthook's docs give for paths with spaces. Check the other hooks for the same problem (the biome job passes `{staged_files}`).

## Don't touch

- Anything outside `lefthook.yml` unless the fix needs it.

## Definition of Done

- [ ] A commit in a worktree whose path has a space runs commitlint and rejects a bad message
- [ ] A commit in a path without spaces still works
