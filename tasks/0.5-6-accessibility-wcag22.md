# 6. WCAG 2.2 AA audit and conformance statement

- **Status:** ready
- **Release:** 0.5
- **Lane:** Core
- **Touches hot files:** No (if a fix needs one, coordinate with the task that holds it)
- **Changes the public API or the protocol:** No
- **Depends on:** none

## Goal

askdare publishes a WCAG 2.2 AA conformance statement for the widget and the default skin, backed by an audit and tests (EAA, EN 301 549 V4.1.1).

## Decisions to read first

ADR-0008 (UI layers), ADR-0011 (headless primitives).

## Files and area

- **Streaming announcements:** `packages/askdare/src/react/messages.tsx` uses a polite `role="log"` with `aria-relevant="additions"`, so text that grows inside an existing node may be read in fragments or not at all, and nothing says the answer is complete. Announce a finished answer once, through a separate status region.
- **Audit:** the WCAG 2.2 criteria that axe can't check:
  - focus not obscured (2.4.11);
  - target size (2.5.8);
  - dragging (2.5.7);
  - consistent help (3.2.6);
  - accessible authentication (3.3.8, relevant once Turnstile lands).
  
  Check them with VoiceOver on iOS and macOS and NVDA on Windows.
- **Tests:** a mobile-viewport Playwright project, and axe with the `wcag22aa` tag in `e2e/a11y.spec.ts`.
- **Statement:** `docs/accessibility.md`, with scope, method, known limitations and the date. It is also published on the site; link it from `docs/compliance.md` section 5, which names it as coming.

## Don't touch

Visual design beyond what a criterion requires.
