# l2. Proactive greeting and an unread badge

- **Status:** blocked (l1, c4)
- **Release:** 0.7 (base branch `release/0.7`)
- **Lane:** Loader
- **Touches hot files:** Yes (`embed/loader.ts`, `bot/define-bot.ts` for the option, `protocol/launcher.ts` if the launcher config grows)
- **Changes the public API or the protocol:** Yes: API snapshot and a minor changeset
- **Depends on:** l1, c4 (which adds the texts and is the last task before this one on `define-bot.ts`)

## Goal

A site can show a short greeting next to the closed launcher after a delay, and the launcher shows a badge when an answer arrives while the chat is closed, accessibly and within the loader budget.

## Decisions to read first

- ADR-0033, [ADR-0019](../docs/adr/0019-compliance-and-guardrails.md) (the AI notice reaches the greeting too), [ADR-0013](../docs/adr/0013-browser-events.md), [ADR-0014](../docs/adr/0014-runtime-language.md).

## Files and area

- `embed/loader.ts` and `chat/host-bridge.ts`: the greeting bubble, its dismissal, the unread count.
- `bot/define-bot.ts` (`widget.greeting` already exists for the chat; the proactive one is a separate option per ADR-0033), `server/launcher.ts`, `protocol/launcher.ts`.
- Browser events for shown, dismissed and clicked greetings, if ADR-0033 adds them (`docs/events.md`).
- Docs: `docs/embedding.md`, `docs/configuration.md`.

## Don't touch

- `react/*`, `chat/store.ts`.

## Definition of Done

- [ ] e2e: greeting shows, dismisses, isn't shown again in the session; badge counts and clears; no focus steal
- [ ] Loader budget passes
- [ ] Minor changeset; snapshot regenerated
- [ ] `pnpm check` passes
