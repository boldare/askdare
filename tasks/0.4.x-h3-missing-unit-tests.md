# H3. Unit tests for untested modules

- **Status:** ready
- **Release:** 0.4.x
- **Lane:** Hygiene
- **Touches hot files:** No
- **Changes the public API or the protocol:** No
- **Depends on:** none (H1 covers `openai/errors.ts`)

## Goal

The modules that are only covered indirectly, or not at all, get direct unit tests, so the larger 0.5 and 0.6 changes can be refactored safely.

## Decisions to read first

ADR-0007 (tooling: vitest), the `typescript-conventions` skill.

## Files and area

In order of risk:
1. `packages/askdare/src/next/create-chat-handler.ts`: environment and secret resolution, a weak `CHAT_SECRET`, duplicate bot IDs, hook isolation (a throwing `onUsage` must not break a turn).
2. `packages/askdare/src/openai/citations.ts`: `file_citation` annotations mapped onto citation events, de-duplication, missing file names.
3. `packages/askdare/src/cli/index.ts` (argument parsing) and `cli/kb-sync.ts` (with a mocked gateway).
4. `packages/askdare/src/chat/prepare-file.ts`: downscaling and stripping metadata.
5. `packages/askdare/src/react/skin/confirm.tsx`: the alertdialog focus trap and Escape.
6. `openai/attachments.ts`, `openai/page-context.ts`, `theme/css.ts`.

Reuse the recorded streams and the mocks already used in `server/handler.test.ts` and `server/stream-turn.test.ts`.

## Don't touch

Library behaviour. If a test finds a bug, fix it in a separate commit with its own changeset.

## Definition of Done

- [ ] Each module above has a test file
- [ ] `pnpm check` passes
