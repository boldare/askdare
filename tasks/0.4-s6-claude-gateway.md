# S6. Spike: a `ModelGateway` for Claude

- **Status:** ready
- **Release:** 0.4 (Spikes lane; ships nothing in 0.4)
- **Lane:** Spikes
- **Touches hot files:** No
- **Changes the public API or the protocol:** No (an experiment and a decision only)
- **Depends on:** none

## Goal

A go or no-go, backed by live measurements, on running askdare on Claude (Anthropic Messages API) instead of OpenAI behind the existing `ModelGateway` port. If go: what each gateway method maps to, what core has to give up or add, and the task files or roadmap line for building it.

## Decisions to read first

- ADR-0002 (OpenAI only, one gateway module, no leaked types, own tool loop). This spike is what would amend or supersede it.
- ADR-0003 (conversation state without a database). Claude has no equivalent of the Conversations API, so this is the main question.
- ADR-0004 (threat model), ADR-0006 (public API), ADR-0012 (telemetry: `gen_ai.provider.name`, usage), ADR-0015 (reply options, built on a tool).
- The `claude-api` skill, before writing any Anthropic call. Its model IDs, beta headers and parameters change often, so check the live docs it links to.
- `spikes/README.md` and the S5b spike as a model for the write-up.

## Why this is not a key swap

`packages/askdare/src/gateway.ts` already defines everything the server needs from a provider, and only `src/openai/` implements it. Four parts of it rely on state that OpenAI keeps and Anthropic doesn't:

| `ModelGateway` | OpenAI today | Claude: what to find out |
|---|---|---|
| `createConversation`, `listMessages`, `deleteConversation` | Conversations API stores the whole conversation under `conv_…` | Messages API is stateless. Message threads (beta) keep a conversation only for a short time, as best effort, so they can cut latency but not replace storage. A store is needed. |
| `runTurn` with `knowledge` | Hosted vector stores + `file_search` + `file_citation` | No hosted vector store. Retrieval has to be our own, with results passed back as content blocks the model can cite. |
| `uploadFile` | Files API, purpose `user_data` | Files API (GA), images and PDFs. Check retention, deletion and limits. |
| `transcribe` | OpenAI transcription | No speech-to-text at Anthropic. Voice needs another provider or is unavailable on Claude. |

## Questions the spike answers

1. **Turn and stream.** Can `runTurn` on Claude emit exactly today's `ProtocolEvent`s from Claude's stream events (text deltas, tool calls, end reasons, `refusal`)? Time to first token with thinking at low effort and `display` omitted, compared with S1's 0.9–1.3 s.
2. **Tool loop.**
   - Map `zodResponsesFunction` tools to `strict: true` Claude tools.
   - Parallel calls return all `tool_result`s in one message, failed ones with `is_error`.
   - The forced final step: we send `tool_choice: 'none'`; check that `none` still works on the model under test (forced `any`/`tool` returns 400 on current models).
   - `suggest_replies` (ADR-0015) still works as a tool.
3. **Conversation state.** The smallest store that keeps ADR-0003's promises: the resume token still carries an encrypted ID, history on reload, deletion with files. Compare an in-memory store (spike only) with what Redis or Postgres would need (the planned `askdare-store-postgres`). Measure whether message threads lower time to first token on long conversations, and say what they cost in ZDR terms.
4. **Knowledge.** One working retrieval path from a folder of documents (what `kb-sync` uploads today) to cited answers, mapped onto our citation protocol. Where embeddings come from: check the live docs for Anthropic's current recommendation, then pick the one with the least new infrastructure. Compare answer quality and citations with `file_search` on the same fixtures.
5. **Caching and cost.** Where the `cache_control` breakpoints go. Dynamic per-request context (page context, identity) sits in `instructions` today, so check that it moves after the cached prefix (for example a mid-conversation system message) and that `cache_read_input_tokens` stays high across turns. Cost per typical turn and per 20-turn conversation against today's OpenAI defaults.
6. **Usage and telemetry.** Map Claude's `usage` onto `TokenUsage` (cache read, cache write, reasoning tokens if reported). What `onUsage` and the OpenTelemetry add-on lose.
7. **Safety and errors.**
   - What replaces `safety_identifier` (check `metadata.user_id`).
   - Handling `stop_reason: "refusal"`, and whether to send server-side `fallbacks`.
   - Map errors onto today's codes (`not_found`, `bot_unavailable`, rate limits), and what `doctor` checks.
8. **Shape of the code.** How a site picks the provider without breaking ADR-0006 (a `gateway` option on the handler, a separate `@boldare/askdare-anthropic` package, or something else), with only one module importing `@anthropic-ai/sdk` and the no-leak test still passing. A recommendation only; the ADR decides.
