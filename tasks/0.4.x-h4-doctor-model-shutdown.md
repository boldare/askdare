# H4. `doctor` warns about models with a shutdown date

- **Status:** ready
- **Release:** 0.4.x
- **Lane:** Hygiene
- **Touches hot files:** No
- **Changes the public API or the protocol:** No (the `/doctor` report is not API, ADR-0006)
- **Depends on:** none

## Goal

An operator learns, from `askdare doctor`, that a model in their bot configuration will stop working, with the date and the replacement OpenAI recommends, before it breaks.

## Why now

OpenAI shuts down `gpt-5`, `gpt-5-mini`, `gpt-5-nano` and `o3` on 2026-12-11; GPT-4o and GPT-4.1 on 2027-01-14; `whisper-1` and the `gpt-4o-*-transcribe` models on 2027-02-26 (deprecations page, checked 2026-11-21). The library hardcodes no model, but adopters' configurations may name these.

## Decisions to read first

- The `openai-api` skill. Check the `openaiDeveloperDocs` MCP server for the `shutdown_date` field of `GET /v1/models/{model}` before using it.
- ADR-0002 (only `src/openai/` imports `openai`).

## Files and area

- `packages/askdare/src/openai/diagnose.ts` already calls `client.models.retrieve(model)`. Read the optional `shutdown_date` and report a warning (not a failure) with the date. Cover the chat model and the transcription model.
- `packages/askdare/src/cli/doctor.ts` prints it. `docs/cli.md` and `docs/troubleshooting.md` describe it.

## Don't touch

Hot files. No list of model IDs in the library: the date comes from the API.

## Definition of Done

- [ ] Unit tests with a model that has `shutdown_date` and one without
- [ ] Docs updated
- [ ] Patch changeset
- [ ] `pnpm check` passes
