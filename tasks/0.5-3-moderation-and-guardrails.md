# 3. Moderation and guardrail hooks

- **Status:** blocked (task 2)
- **Release:** 0.5
- **Lane:** Core
- **Touches hot files:** Yes (`bot/define-bot.ts`, possibly `protocol/*`)
- **Changes the public API or the protocol:** Yes: API snapshot, ADR-0019 and a minor changeset
- **Depends on:** 2

## Goal

An operator can stop harmful or off-policy messages before they reach the model, and answers before they reach the visitor, with OpenAI's moderation or their own rules.

## Decisions to read first

- ADR-0019, ADR-0004, ADR-0012 (server hooks: isolated, never break a turn).
- The `openai-api` skill. Check the `openaiDeveloperDocs` MCP server for how moderation results are returned with Responses today before designing anything.

## Files and area

As ADR-0019 decides; at the time of writing:
- `moderation` in `defineBot`: off by default, or on for input, output or both.
- `onInput(message, context)`: returns allow, block (with a text for the visitor) or a redacted message. `onOutput` does the same for a finished answer; streaming policy (hold back or retract) is decided in the ADR.
- A blocked turn ends with the existing `content_blocked` code. Nothing blocked is logged as content.
- `toolResults: 'untrusted'` (off by default) wraps tool results as untrusted data for the model (prompt-injection hardening, ADR-0004).
- Every option is off by default: a bot that sets none of them behaves exactly as in 0.4. Add a test for that.
- Docs: a new `docs/guardrails.md`, and replace "Coming in 0.5" in `docs/compliance.md` section 6 with a summary that links it.

## Don't touch

`i18n/texts.ts` (task 5); new texts are added there by task 5 or after it.
