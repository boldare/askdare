# p2. The `AdminStore` port, its contract suite and a memory store

- **Status:** blocked (x3)
- **Release:** 0.7 (base branch `release/0.7`)
- **Lane:** Ports
- **Touches hot files:** No (a new module, `packages/askdare/src/admin/`)
- **Changes the public API or the protocol:** Yes: API snapshot and a minor changeset
- **Depends on:** x3

## Goal

The `AdminStore` port from ADR-0032 exists in the core with `memoryAdminStore()` for tests and an `adminStoreContract` suite every implementation runs, plus the `AdminDashboard` type the add-on plugs into the console with. a1, a2, a3 and c5 build on it.

## Decisions to read first

- [ADR-0032](../docs/adr/0032-admin-store.md) (decisions 2, 6, 9 and 11), [ADR-0016](../docs/adr/0016-admin.md).
- `packages/askdare/src/conversations/port.ts`, `conversations/memory.ts` and `testing/conversation-store-contract.ts`: copy their shape.

## Files and area

- `packages/askdare/src/admin/port.ts`: `AdminStore` and its record, count, query and page types as decision 2 sketches them, names final here. Daily rows are per bot and model (turns) and per bot (conversations, ratings, leads, handoffs by state).
- `packages/askdare/src/admin/memory.ts`: `memoryAdminStore()`, with the production warning `memoryStore()` gives.
- `packages/askdare/src/admin/dashboard.ts`: the `AdminDashboard` type (inlined assets and read handlers), with no implementation; c5 serves it, a3 implements it.
- `packages/askdare/src/testing/admin-store-contract.ts`, exported from `@boldare/askdare/testing`, called as `(name, create, { describe, it, expect, …options })` and deleting everything it writes.
- Exports as decision 11 lists; snapshot regenerated.

## Don't touch

- `server/handler.ts` and `next/create-chat-handler.ts`: c5 adds the `admin` option, the writes, delete, `sweep()` and the console.
- `packages/askdare-postgres/` and `packages/askdare-upstash/` (a1, a2).

## Definition of Done

- [ ] The contract suite runs against the memory store: every write, the fixed queries with their ranges, limits and cursors, `rating: null`, counts of handoffs and leads, `deleteConversation` (idempotent, daily rows kept), `sweep` of records and of daily rows
- [ ] No lead values or handoff details anywhere in the types (ADR-0032, decision 6)
- [ ] Minor changeset; snapshot regenerated
- [ ] `pnpm check` passes
