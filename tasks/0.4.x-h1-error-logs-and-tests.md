# H1. OpenAI error mapping: tests and a log audit

- **Status:** ready
- **Release:** 0.4.x
- **Lane:** Hygiene
- **Touches hot files:** No
- **Changes the public API or the protocol:** No
- **Depends on:** none

## Goal

Every OpenAI failure maps to the right stable error code, and nothing an operator's logs receive can carry message content, checked by tests rather than by reading the code.

## Decisions to read first

- ADR-0004 (threat model): "Logs contain no message content or PII by default. Errors map to stable codes."
- `docs/troubleshooting.md`, keyed by error code.

## Files and area

- `packages/askdare/src/openai/errors.ts` has no unit test. Cover each branch:
  - `NotFoundError` for a model or a conversation;
  - rate limits with `retry-after-ms` and `retry-after`;
  - connection errors, timeouts and user aborts;
  - content refusals;
  - unknown `APIError`s.
- `redacted()` already keeps only status, code, request ID and a `scrub`bed message. Find out whether an OpenAI error message can quote request input (for example invalid-input or content errors; check the `openaiDeveloperDocs` MCP server and recorded fixtures). If it can, drop the message from the logged cause for those cases and keep code, status and request ID.
- `packages/askdare/src/next/create-chat-handler.ts`, `report()`: when there is no `onError`, it logs `error.cause`. Add a test that a cause holding a request body or an API key never reaches `console.error` in full.

## Don't touch

Hot files. The `ErrorCode` export belongs to 0.5 (ADR-0020).

## Definition of Done

- [ ] Unit tests for every branch of `openai/errors.ts`
- [ ] A test of `report()` with a hostile cause
- [ ] A fix if an error message can carry input, with a patch changeset
- [ ] `pnpm check` passes
