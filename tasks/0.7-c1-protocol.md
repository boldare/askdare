# c1. Protocol: handoff and forms

- **Status:** blocked (x1, x2)
- **Release:** 0.7 (base branch `release/0.7`)
- **Lane:** Core
- **Touches hot files:** Yes (`protocol/*`, `docs/protocol.md`)
- **Changes the public API or the protocol:** Yes: protocol, additive within v1
- **Depends on:** x1, x2

## Goal

The SSE protocol carries what ADR-0030 and ADR-0031 decide (a handoff state and a form card, or whatever the ADRs choose), with schemas, validation and docs, so the client (c2) and the server (c3) build on one definition.

## Decisions to read first

- ADR-0030, ADR-0031, [`docs/protocol.md`](../docs/protocol.md) (versioning rules), [ADR-0015](../docs/adr/0015-reply-options.md), [ADR-0017](../docs/adr/0017-tool-renderers.md).

## Files and area

- `packages/askdare/src/protocol/events.ts`, `schemas.ts`, `validate.ts`, `tool-ui.ts` (if forms ride on `tool.ui`), and a request schema for submitting a form, if ADR-0031 adds an endpoint.
- `docs/protocol.md`: the new events and fields, with examples.
- Old clients must ignore the new events: a test that the 0.6 client's validator passes a stream with them.

## Don't touch

- `chat/*` (c2), `server/handler.ts` (c3).

- [ ] Schema and validation tests for each new event, and for unknown fields
- [ ] `docs/protocol.md` updated
- [ ] Minor changeset
