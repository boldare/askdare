# a2. `postgresConversations()`

- **Status:** blocked (1, a1)
- **Release:** 0.6 (base branch `release/0.6`)
- **Lane:** Add-ons
- **Touches hot files:** No
- **Changes the public API or the protocol:** Yes: `@boldare/askdare-postgres` exports (minor changeset for that package)
- **Depends on:** 1, a1

## Goal

A site can keep its conversations in its own Postgres with `postgresConversations({ url })`, swept after a retention period it chooses, and the store passes the same contract suite as the built-in ones.

## Decisions to read first

- [ADR-0024](../docs/adr/0024-conversation-store.md) (Proposed), decisions 1, 3, 6 and 9.
- `spikes/s7-store/`: `pg-store.ts`, `schema.sql`, `contract.ts`, and `FINDINGS.md` questions 1, 5 and 7.

## Files and area

- `packages/askdare-postgres/src/conversations/`: the store with `pg` only, items as `jsonb`, indexing only `type` and item ID, file IDs found with a JSON path. Atomic appends with `expect` versions, keyset paging, a context window cut at a visitor message, `delete` returning file IDs, `sweep(idleSince, limit)` with `for update skip locked`, and `diagnose()` reporting the schema version.
- Its migration in `src/schema/` (a1's machinery), and one export line in `src/index.ts`.
- `sweep`: export it, and document a cron route for Vercel and a scheduled job for Heroku in the README. The route deletes through the same path as `DELETE /conversation` (files, and the admin store when there is one).
- Logs: nothing about stored values, ever.
