# e1. End-to-end test of a chat turn kept in Postgres

- **Status:** in progress (`test/postgres-turn-e2e`)
- **Release:** 0.6 (base branch `release/0.6`)
- **Lane:** CI
- **Touches hot files:** No
- **Changes the public API or the protocol:** No
- **Depends on:** 2, a2

## Goal

A real chat turn runs end to end on `postgresConversations()` from `@boldare/askdare-postgres`: send a message, reload and get the history back, continue the conversation (with a tool call), delete it, and check that the conversation and its rows are gone. Tasks 2 and a2 each left this test to whichever merged second; neither added it.

## Decisions to read first

- ADR-0024 (conversation stores, stateless turns), `packages/askdare-postgres/README.md`.

## Files and area

- `site/app/api/e2e-postgres/[...path]/route.ts`: a test-only chat route with one bot on `postgresConversations()`. It answers 404 unless `ASKDARE_E2E_DATABASE_URL` is set, which only `playwright.config.ts` does, so the demo is unchanged.
- `e2e/postgres.spec.ts` and `e2e/support/database.ts`: the test, in a schema of its own (`askdare_e2e`) of the database at `ASKDARE_POSTGRES_TEST_URL`. Skipped locally without it, an error in CI.
- `e2e/servers/mock-openai.mjs`: stateless responses (no `conversation`, `store: false`, the whole history as input), with `response.output` filled in.
- `.github/workflows/ci.yml`: the `e2e` job gets the same pgvector service as `check`.

## Don't touch

- Library code: `openai/*`, `bot/define-bot.ts`, `server/stream-turn.ts`, `server/handler.ts` belong to k2 and t1. A bug found here gets a failing test and a report.

## Definition of Done

- [ ] The test passes locally against `packages/askdare-postgres/docker-compose.yml`
- [ ] CI provides the database to the e2e job, without credentials in URLs
- [ ] `pnpm check` passes
