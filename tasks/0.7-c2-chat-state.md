# c2. Chat state: handoff, forms and the reconnect fix

- **Status:** blocked (c1)
- **Release:** 0.7 (base branch `release/0.7`)
- **Lane:** Core
- **Touches hot files:** Yes (`chat/state.ts`, `chat/reducer.ts`, `chat/store.ts`, `chat/events.ts`)
- **Changes the public API or the protocol:** Yes: API snapshot and a minor changeset (new state fields seen by `useChat`)
- **Depends on:** c1

## Goal

The headless client knows when a conversation is being handed off, shows a form card's state (open, submitting, sent, errors per field) and submits it. Also: "Reconnecting…" disappears as soon as a resume succeeds, not at the next text or status event (ROADMAP, "Known gaps").

## Decisions to read first

- ADR-0030, ADR-0031, [ADR-0011](../docs/adr/0011-react-api-and-inline-chat.md), [ADR-0027](../docs/adr/0027-stream-resume.md).

## Files and area

- `chat/state.ts`, `chat/reducer.ts`: the new state and events from c1.
- `chat/store.ts`: submitting a form (with the access token, as feedback does), and clearing `activity` after a successful resume (it is set to `status.reconnecting` around line 517).
- `chat/chat-client.ts`: the request for a form submit, if ADR-0031 adds an endpoint.
- `chat/testing/fake-server.ts` and the fixtures.

## Don't touch

- `react/*` (c4), `i18n/texts.ts` (c4 adds the texts).

## Definition of Done

- [ ] Reducer and store tests for each new state, a failed submit, a handoff that fails, a resume that clears "Reconnecting…"
- [ ] React size budget still passes
- [ ] Minor changeset; snapshot regenerated
- [ ] `pnpm check` passes
